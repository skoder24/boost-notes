# Repository guidance

## Purpose

This repository contains beginner-focused learning plans, project ideas, and setup guides related to technical careers and foundational tools. Keep the material practical, approachable, and clear about which steps are optional.

## Content and attribution

- Distinguish original guidance from material adapted from other sources.
- Preserve source links, attribution, and applicable license notices when adapting material. Do not copy source text unnecessarily.
- Describe schedules and recommendations as suggestions unless an authoritative source establishes them as requirements.
- Verify claims against current, authoritative documentation, especially for software installation and platform-specific behavior.

## Writing and structure

- Keep guides understandable to readers who may be new to the topic; explain unfamiliar terms and commands when they first appear.
- Label the environment for commands, such as PowerShell, Ubuntu in WSL, or a container.
- Use hyphenated filenames and sentence case for headings.
- Keep paragraphs on a single line in the Markdown source.
- Keep beginner content focused: explain the next useful step without making advanced tools sound like prerequisites.

## Command and safety guidance

- Explain what example commands do and where to run them.
- Clearly warn before commands that can delete data, change system settings, or remove packages or environments.
- Prefer examples that use sample or project-local files; do not include real credentials or personal data.
- Check platform-specific syntax and prerequisites before changing command examples.

## Changes and review

- Keep edits focused on the relevant guide and maintain consistency across related documents.
- Review Markdown links and references affected by a change.
- Check command examples for accuracy, context, and clearly stated risks.
- This repository currently has no configured automated test suite; report that plainly rather than implying automated checks were run.
